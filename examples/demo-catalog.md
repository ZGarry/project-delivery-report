# 用户认可的汇报案例写法

以下四类写法来自实际交付中的用户反馈。本公开目录保留可复用的组织方式；真实业务报告、截图、账号资料和原始附件由项目方在受控位置保存，未随此 skill 发布。

大型交付选最接近的一类作为参考；小改动保持简报。每次重新采集当前环境的数据和截图，不能沿用历史结论。

## 1. 聊天功能 E2E 验收

适用：一组业务流程验收、补充截图、处理异常及解释替换进度。

值得复用：

- 首屏交代实际完成范围、核心场景、截图入口和剩余缺口。
- 业务入口写成能照着操作的路径，截图对应场景与断言，接口结果提供数据对账。
- 保留首次失败、后续重复结果及未知根因，不把“后来成功”写成“根因修复”。
- 分别判断独立测试环境可用、主环境部署、完整旧版等价和正式替换。

选定核心场景通过不能直接写成全量替换通过。

## 2. 旧版与新版逐项对照

适用：功能替换、迁移、要求保持原有体验的项目。

值得复用：

- 固定旧版功能清单与可获得的基线，按同场景比较能力、界面、交互和数据结果。
- 同一条目并排呈现旧新证据，标明环境、时间、版本和未验证项。
- 性能记录、容量门槛和历史异常能定位原始附件。

历史画面不能证明当前部署或业务切换。报告较大时按业务阅读路径组织，主要结论和缺口仍放首屏。

## 3. 账号管理页面改版

适用：新增页面、界面精简、面向使用者的功能交付。

值得复用：

- 围绕找账号、复制信息、确认角色介绍结果，把实际使用路径与界面变化连起来。
- 前后变化表配真实页面、手机视图和交互验收，说明数量口径与环境边界。
- 说明已观察到的便利，未测量的时间节省和业务收益保持未测量。
- 遮盖证据中的账号与密码，核验结论有回读证据，不在公开附件保存认证材料。

目录数量与登录证明只代表采集时状态；不能据此宣称当前账号有效。

## 4. 页面性能优化

适用：页面速度、接口性能和数据库查询优化。

值得复用：

- 同表列旧值、新值、单位、变化幅度、统计量和测量口径。
- 写明前后版本、实际环境、负载、样本量及起止点，保留各轮原始结果。
- 把用户可用时间与接口耗时、连接数、查询次数对应起来，同时核验权限、数据结果和运行影响。
- 保留未改善指标，不把接口提速等同于整站提速、长期稳定或财务收益。

不要从其他案例复制性能数字。不同条件只并列展示，未建立因果关系时说明限制。

## 保存自己的实际样本

在项目受控目录保存报告、相对路径截图和必要附件，记录原始位置、采集时间、环境、版本及文件哈希。先确认公开范围，再决定是否分发实际证据。目录和哈希可帮助查找、核对文件，不能替代业务验收。
